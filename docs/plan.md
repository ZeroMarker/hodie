# 英语学习应用开发计划

2026-10-14(2026-10-21 更新)

## 假设

本计划按 12 周、1 到 2 人团队、Web 优先的前提制定;以下假设若不成立,需要调整范围和排期。

- **目标用户**:备考英语的中文母语学习者(四六级、考研、雅思、托福等),产品定位为长期学习,见 [产品定位](positioning.md)。
- **平台**:移动端优先的 Web 应用(PWA),验证后再考虑原生 App。
- **核心玩法**:间隔重复背单词(SRS)、例句听力、AI 口语对话。
- **团队与周期**:1 到 2 人,约 12 周。

## 技术选型

整体原则是早期不拆服务,用托管服务把运维负担降到最低。

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 前端与后端 | Next.js(App Router)+ TypeScript + Tailwind | 一套代码覆盖 PWA 与 API,早期不拆服务 |
| 数据库 | Aiven PostgreSQL(`mammoth` 服务的 `hodie` 库) | 词库已导入 `vocab` schema;用户数据放 `app` schema |
| ORM 与迁移 | Drizzle | 只管理 `app` schema |
| 认证 | Auth.js | 邮箱和 Google 登录 |
| 语音 | 浏览器 Web Speech API,后期换云端 TTS/ASR | 先低成本验证 |
| AI 对话 | Claude API | 口语陪练、语法纠错、造句 |
| 部署 | Vercel + Aiven 连接池 | 运维负担最小 |

模块划分、表结构、数据流和环境见 [架构设计](architecture.md)。

词汇图谱继续用 PostgreSQL,不引入 Neo4j:WordNet 约 50 万条关系,用关系表加递归查询即可;相似词推荐用 pgvector。图谱可视化用 Cytoscape.js。数据来源为 Open English WordNet(关系)、ECDICT(中文释义)、wordfreq(词频)、CEFR-J(CEFR 等级),详见 [词库来源选择](vocab-sources.md)。ConceptNet 常识关系和 LLM 自动抽取关系放到发布之后,避免挤压 SRS 主线。

词源作为同一张图谱的扩展,不另建系统。主数据来源是 Wiktionary dump(CC BY-SA,需要署名,衍生数据库还要考虑 share-alike 的影响);Etymonline 是商业站点,不批量抓取,只作人工参考;PIE 数据库的许可证待核对。完整的 PIE 语系图谱和语义变化追踪放到发布之后。

2. **阶段 1:MVP 核心(第 2 到 5 周)**
    - 账号体系和用户资料(Auth.js)。
    - 选词书、词汇量测试、新词排序与干扰控制。
    - 词卡:释义、音标、浏览器发音、例句、搭配;多义词用 `core_sense_id` 定核心义。
    - SRS 调度用 ts-fsrs;L0 到 L3 题型、自动评分、每日队列、连续打卡、进度统计;规则见 [单词学习方案](word-learning-plan.md)。
    - 验收:用户能独立完成「注册 → 学新词 → 次日复习」的闭环。
    - 实施顺序(每步可单独上线):
        - [x] 账号:Auth.js 邮箱魔法链接(Resend)和 Google 登录,`app` schema 加 Auth.js 四张表,数据库会话(2026-10-21)。Resend 发信已配置,Google OAuth 客户端待配置。
        - [x] 选词书与新词队列:注册后按考试选词书;词汇量测试每档 5 题,从第 1 档起连续通过两档以上的整档跳过;新词 NGSL 优先再按词频,同批避开形近、同义近义和同上位词(2026-10-21)。
        - [x] 学习词卡:新词先看词卡(释义、例句、搭配、浏览器发音),再做选择题(2026-10-21)。
        - [x] SRS:ts-fsrs 调度,服务端判对错并按耗时中位数自动评分;L1 选择、L2 例句挖空、L3 拼写,L4 暂按 L3 出题;答错的词本轮末尾再出现一次(2026-10-21)。
        - [x] 打卡与进度:首页显示待复习、今日新词、连续打卡、已学、已掌握(S ≥ 21 天)和近 7 天作答(2026-10-21)。
        - [x] 闭环验收:线上新账号 10-21 注册并学 10 个新词,10-22 复习 14 次(含答错重现)、再学 10 个新词,下次复习分布在之后一周(2026-10-22)。
    - 已知问题:同形异义词(如 found 既是 find 的过去式,又是「建立」)的挖空题,例句可能与核心义不符;阶段 2 按词义筛选例句。提交作答时逐条查询,本地到班加罗尔约 2 秒一批,内测前优化。目前固定浅色主题(系统深色模式下原先会白底浅灰字,2026-10-21 修复)。
3. **阶段 2:内容与练习(第 6 到 8 周)**
    - 听写、例句填空等题型补齐,错题本、词书切换、自适应。
    - 云端 TTS 预生成单词和例句音频,存对象存储。2026-10-22 决定暂缓,继续用浏览器朗读;方案见 [架构设计](architecture.md) 的「发音」一节。

    - PWA 离线缓存和作答离线同步,保证通勤场景可用。
4. **阶段 3:AI 能力(第 9 到 10 周)**
    - AI 口语对话:按场景和难度分级,带实时语法与用词纠正。
    - L4 造句批改、语境短故事;用 pgvector 做相似词推荐。
    - 控制成本:`ai_usage` 限额、`ai_cache` 缓存、简单任务用小模型。
5. **阶段 4:打磨与发布(第 11 到 12 周)**
    - 埋点和数据看板。
    - 性能优化、无障碍、深色主题、隐私合规(数据导出和删除)。
    - 20 到 50 人小范围内测,按反馈迭代后公开发布。

## 主要风险与应对

最大的两个风险是词库版权和 AI 成本,都需要在阶段 0 到 1 内定下规则。

| 风险 | 应对 |
| --- | --- |
| 词库版权 | 以 ECDICT 为主干,只用开放许可来源,见 [词库来源选择](vocab-sources.md) |
| AI 成本失控 | 设置用量上限和缓存,免费版限额 |
| 留存低 | 先做好打卡、提醒和进度反馈,再扩展功能 |
| 发音质量 | 先用现成 TTS,保留人工录音的扩展口 |
