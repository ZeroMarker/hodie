# 英语学习应用开发计划

2026-10-14

## 假设

本计划按 12 周、1 到 2 人团队、Web 优先的前提制定;以下假设若不成立,需要调整范围和排期。

- **目标用户**:中文母语的成人学习者,主要练词汇和听说。
- **平台**:移动端优先的 Web 应用(PWA),验证后再考虑原生 App。
- **核心玩法**:间隔重复背单词(SRS)、例句听力、AI 口语对话。
- **团队与周期**:1 到 2 人,约 12 周。

## 技术选型

整体原则是早期不拆服务,用托管服务把运维负担降到最低。

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 前端 | Next.js + TypeScript + Tailwind | 一套代码覆盖 PWA 与 SEO |
| 后端 | Next.js API Routes 或 Node + Fastify | 早期不拆服务 |
| 数据库 | PostgreSQL(Supabase 或自建) | 用户、词库、学习记录 |
| 认证 | Supabase Auth 或 Auth.js | 邮箱和 Google 登录 |
| 语音 | 浏览器 Web Speech API,后期换云端 TTS/ASR | 先低成本验证 |
| AI 对话 | Claude API | 口语陪练、语法纠错、造句 |
| 部署 | Vercel + 托管 Postgres | 运维负担最小 |

## 里程碑

交付分五个阶段,第 5 周末得到可用的 MVP,第 12 周公开发布。

1. **阶段 0:准备(第 1 周)**
    - 确认目标人群、核心卖点和成功指标(如 7 日留存、每日学习时长)。
    - 搭好项目骨架、CI、代码规范和数据库迁移。
    - 整理词库来源(CET-4/6、雅思、高频 3000 词),确认许可证。
2. **阶段 1:MVP 核心(第 2 到 5 周)**
    - 账号体系和用户资料。
    - 词卡:释义、音标、发音、例句。
    - SRS 调度,先用 SM-2,再换 FSRS。
    - 每日学习与复习队列、连续打卡、进度统计。
    - 验收:用户能独立完成「注册 → 学新词 → 次日复习」的闭环。
3. **阶段 2:内容与练习(第 6 到 8 周)**
    - 选择、拼写、听写、例句填空四种题型。
    - 听力片段(TTS 生成加人工抽检)。
    - 错题本和词书切换。
    - PWA 离线缓存,保证通勤场景可用。
4. **阶段 3:AI 能力(第 9 到 10 周)**
    - AI 口语对话:按场景和难度分级,带实时语法与用词纠正。
    - 为生词自动生成语境例句。
    - 控制成本:限制对话轮数,缓存常见请求,简单任务用小模型。
5. **阶段 4:打磨与发布(第 11 到 12 周)**
    - 埋点和数据看板。
    - 性能优化、无障碍、隐私合规(数据导出和删除)。
    - 20 到 50 人小范围内测,按反馈迭代后公开发布。

## 数据模型(初版)

初版共 6 张表,以 `user_word_state` 保存 SRS 状态,`review_logs` 保存每次作答。

| 表 | 用途 |
| --- | --- |
| `users` | 账号和偏好(目标等级、每日新词量) |
| `words` | 词条、音标、释义、词频、等级 |
| `examples` | 例句,关联 `words`,含音频 URL |
| `user_word_state` | 用户对每个词的 SRS 状态(间隔、难度、下次复习时间) |
| `review_logs` | 每次作答记录,用于统计和算法调参 |
| `conversations` / `messages` | AI 对话历史 |

## 主要风险与应对

最大的两个风险是词库版权和 AI 成本,都需要在阶段 0 到 1 内定下规则。

| 风险 | 应对 |
| --- | --- |
| 词库版权 | 优先用开源词库(如 ECDICT),上线前核对许可证 |
| AI 成本失控 | 设置用量上限和缓存,免费版限额 |
| 留存低 | 先做好打卡、提醒和进度反馈,再扩展功能 |
| 发音质量 | 先用现成 TTS,保留人工录音的扩展口 |

## 需要确认的事项
