# 英语学习应用开发计划

2026-10-14

## 假设

本计划按 12 周、1 到 2 人团队、Web 优先的前提制定;以下假设若不成立,需要调整范围和排期。

- **目标用户**:中文母语的成人学习者,主要练词汇和听说。
- **平台**:移动端优先的 Web 应用(PWA),验证后再考虑原生 App。
- **核心玩法**:间隔重复背单词(SRS)、例句听力、AI 口语对话。
- **团队与周期**:1 到 2 人,约 12 周。

## 技术选型

整体原则是早期不拆服务,用托管服务把运维负担降到最低。

| 层 | 选择 | 理由 |
| --- | --- | --- |
| 前端 | Next.js + TypeScript + Tailwind | 一套代码覆盖 PWA 与 SEO |
| 后端 | Next.js API Routes 或 Node + Fastify | 早期不拆服务 |
| 数据库 | PostgreSQL(Supabase 或自建) | 用户、词库、学习记录 |
| 认证 | Supabase Auth 或 Auth.js | 邮箱和 Google 登录 |
| 语音 | 浏览器 Web Speech API,后期换云端 TTS/ASR | 先低成本验证 |
| AI 对话 | Claude API | 口语陪练、语法纠错、造句 |
| 部署 | Vercel + 托管 Postgres | 运维负担最小 |

词汇图谱继续用 PostgreSQL,不引入 Neo4j:WordNet 约 50 万条关系,用关系表加递归查询即可;相似词推荐用 pgvector。图谱可视化用 Cytoscape.js。数据来源为 WordNet(关系)、ECDICT(中文释义)、SUBTLEX-US(词频)、Oxford 3000(CEFR,需核对许可证)。ConceptNet 常识关系和 LLM 自动抽取关系放到发布之后,避免挤压 SRS 主线。

词源作为同一张图谱的扩展,不另建系统。主数据来源是 Wiktionary dump(CC BY-SA,需要署名,衍生数据库还要考虑 share-alike 的影响);Etymonline 是商业站点,不批量抓取,只作人工参考;PIE 数据库的许可证待核对。完整的 PIE 语系图谱和语义变化追踪放到发布之后。

## 里程碑

交付分五个阶段,第 5 周末得到可用的 MVP,第 12 周公开发布。

1. **阶段 0:准备(第 1 周)**
    - 确认目标人群、核心卖点和成功指标(如 7 日留存、每日学习时长)。
    - 搭好项目骨架、CI、代码规范和数据库迁移。
    - 整理词库来源(CET-4/6、雅思、高频 3000 词、WordNet、ECDICT、SUBTLEX-US、Oxford 3000、Wiktionary dump),确认许可证。
2. **阶段 1:MVP 核心(第 2 到 5 周)**
    - 账号体系和用户资料。
    - 词卡:释义、音标、发音、例句,导入 WordNet 、词频和 CEFR 等级,展示同义词、反义词和词根词缀拆解(词源数据随 Wiktionary 解析导入)。
    - SRS 调度,先用 SM-2,再换 FSRS。
    - 每日学习与复习队列、连续打卡、进度统计。
    - 验收:用户能独立完成「注册 → 学新词 → 次日复习」的闭环。
3. **阶段 2:内容与练习(第 6 到 8 周)**
    - 选择、拼写、听写、例句填空四种题型。
    - 听力片段(TTS 生成加人工抽检)。
    - 错题本、词书切换,以及词族展开、词源链和图谱可视化(Cytoscape.js)。
    - PWA 离线缓存,保证通勤场景可用。
4. **阶段 3:AI 能力(第 9 到 10 周)**
    - AI 口语对话:按场景和难度分级,带实时语法与用词纠正。
    - 为生词自动生成语境例句;用 pgvector 做相似词推荐;AI 辅助抽取词间关系,须人工审核;基于已入库的词源数据用 LLM 生成词源讲解,避免编造。
    - 控制成本:限制对话轮数,缓存常见请求,简单任务用小模型。
5. **阶段 4:打磨与发布(第 11 到 12 周)**
    - 埋点和数据看板。
    - 性能优化、无障碍、隐私合规(数据导出和删除)。
    - 20 到 50 人小范围内测,按反馈迭代后公开发布。

## 数据模型(初版)

初版共 6 张表,以 `user_word_state` 保存 SRS 状态,`review_logs` 保存每次作答。

| 表 | 用途 |
| --- | --- |
| `users` | 账号和偏好(目标等级、每日新词量) |
| `words` | 词条、音标、释义、词频、等级 |
| `examples` | 例句,关联 `words`,含音频 URL |
| `user_word_state` | 用户对每个词的 SRS 状态(间隔、难度、下次复习时间) |
| `review_logs` | 每次作答记录,用于统计和算法调参 |
| `conversations` / `messages` | AI 对话历史 |

为支持词汇图谱,再增加以下内容:

- `senses`:词义节点,解决多义词(如 bank 的「银行」与「河岸」)。
- `relations`(src, dst, type):同义、反义、上位、下位、派生等关系。
- `morphemes`:词根词缀及其与词的关联(如 spect → inspect、respect)。
- `words` 增加 CEFR 等级和词频排名列。

为支持词源,再增加以下内容:

- `languages`:语言节点(如 Latin、Old French)。
- `relations.type` 增加 `inherited`、`borrowed_from`、`derived_from`、`semantic_shift`。
- `morphemes` 增加来源语言和原义列(如 spect 来自 Latin specere,「看」)。

## 学习设计原则

依据见 [语言系统与记忆方法研究](research.md);这些原则约束阶段 1 到 3 的功能设计。

1. 练习以主动提取为主:先回忆再看答案,选择题只做入门,逐步过渡到拼写和造句。
2. 间隔重复先用 SM-2,再换 FSRS;保留 `review_logs` 供参数拟合。
3. 每个词至少有音、义、例句三个通道,具体名词加图。
4. 控制干扰:同一天的新词避开形近词和同类近义词,稍后再做辨析练习。
5. 图谱和词源用于复习后期的精细加工,初学时不把关联信息全部铺开。
6. 按词频分层,先学高频词。
7. 每日学习流程分三段:复习到期卡片(提取)→ 学新词(多通道)→ 一个语境任务(阅读或听力片段,含刚学过的词)。
8. 题型按熟练度进阶:选择题 → 填空 → 拼写听写 → 造句,由 FSRS 的稳定性指标触发。
9. 以语块和例句为单位学习,词卡展示常见搭配。
10. 反馈要具体:AI 纠错指出错在哪、为什么、怎么改。
11. 游戏化只做动机层(打卡、每日目标、进度可视化),不做排行榜。
12. 根据近期正确率和响应时间自适应调整新词数量和题型难度。
13. 自适应出题优先练薄弱点:错得多的词和题型(刻意练习)。
14. 进阶题型加入费曼式输出:用户用自己的话解释词义或造句。
15. 阶段 3 的 AI 对话按任务型教学设计:围绕写邮件、点餐等真实任务展开。
16. 阶段 3 让 AI 把一组生词编成短故事或语境段落(故事化记忆)。
17. 阶段 2 在图谱上点亮用户已掌握的词,作为进度可视化。
18. 音素层的最小对立对听辨(l/r、th、长短元音)和句法专项练习放在发布之后。

第 16 到 18 条依据见 [语言系统与记忆方法研究](research.md)。词源只作辅助精细加工,不作主线。

第 7 到 15 条依据见 [学习形式研究](learning-formats.md)。跟读录音是否纳入 12 周范围,取决于对麦克风权限、音频存储和隐私合规的评估,待确认。

## 主要风险与应对

最大的两个风险是词库版权和 AI 成本,都需要在阶段 0 到 1 内定下规则。

| 风险 | 应对 |
| --- | --- |
| 词库版权 | 优先用开源词库(如 ECDICT),上线前核对许可证 |
| AI 成本失控 | 设置用量上限和缓存,免费版限额 |
| 留存低 | 先做好打卡、提醒和进度反馈,再扩展功能 |
| 发音质量 | 先用现成 TTS,保留人工录音的扩展口 |
